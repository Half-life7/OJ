# 测试数据 ZIP 校验器（2A）

`internal/testcase` 是纯标准库的内存校验模块。它读取 ZIP、验证测试点及分值并返回内容摘要，不创建文件、不连接数据库、不启动程序，也不分配 `data_version`。

本批没有增加上传 API、数据管理页面、持久化或比赛版本锁定。后续上传服务须先通过权限与请求体校验，再调用本模块；不能据本模块通过测试宣称完整题目或判题功能已交付。

## 调用接口

```go
dataset, err := testcase.Parse(
    ctx,
    bytes.NewReader(zipBytes),
    int64(len(zipBytes)),
    map[string]int64{"1": 40, "2": 60},
    testcase.DefaultLimits(),
)
```

- 调用者提供有效上下文、在整个解析期间保持不变的 `io.ReaderAt`、准确的归档长度、独立分值表以及显式限额。零值 `Limits` 不代表无限制，也不会悄悄采用默认配置。
- 成功返回 `Dataset`：按 ID 排序的 `Cases`、SHA-256 `Digest`、输入输出总字节数 `TotalBytes` 和总分 `TotalScore`。
- 每个 `Case` 包含原始 `ID`、`Input`、`Output` 字节和 `Score`。二进制内容、空内容、空白和换行均保留，不进行编码转换或行尾归一化。
- 失败始终返回零值 `Dataset`，不返回部分可用结果。调用者不得在解析完成前发布或使用任何测试点。
- 返回的字节切片归调用者所有，修改切片不会自动重算摘要；持久化版本时应将数据和摘要作为同一不可变快照保存。

## 支持的 ZIP 格式

格式限定为 ZIP32、单卷、Store 或 Deflate 压缩。拒绝 ZIP64、加密、自解压前缀、未声明的尾随垃圾及不支持的压缩方式。普通 ZIP 注释和合法的非 ZIP64 extra 字段可存在，但不计入内容摘要。

归档成员必须全在根目录，只接受成对的 `<id>.in` 和 `<id>.out`：

```text
1.in
1.out
2.in
2.out
```

- ID 为 1～64 个 ASCII 字母、数字、下划线或连字符，首字符必须是字母或数字；扩展名严格为小写 `.in`、`.out`。
- 按原始 ID 配对，大小写折叠后也不能存在冲突。`A.in` 与 `a.out` 不会被自动合并；重复成员同样拒绝。
- 拒绝目录、链接、设备、管道等非普通文件，拒绝绝对路径、目录分隔符、盘符、控制字符、点路径和 Windows 保留设备名（CON、PRN、AUX、NUL、COM1～COM9、LPT1～LPT9）。不先清理或截断文件名再接受。
- 不接受额外的 `.zip`、配置、说明等成员，也不递归解压成员内容。输入输出内部可以是任意二进制字节，不检查其是否恰好具有压缩文件的字节特征。
- 不依赖 `GODEBUG=zipinsecurepath` 的行为，校验器自行执行文件名及类型检查。

## 分值与摘要

分值表使用原始 ID 作为键，必须精确覆盖归档中的全部测试点。分值是非负 `int64`，允许个别零分点，但总分必须大于零；缺失、额外键、负数和加总溢出均拒绝。本批不定义 ZIP 内 manifest，也不替调用者分摊默认分值。

测试点按 ID 的字节顺序排列，例如 `1`、`10`、`2`。内容摘要采用以下固定编码后计算 SHA-256：

1. 域标识 `biue-testdata-v1`，后接一个零字节。
2. 测试点数量，以 8 字节大端无符号整数编码。
3. 依排序逐点写入：ID 长度及字节、输入长度及字节、输出长度及字节、分值。各长度及分值均为 8 字节大端无符号整数。

ZIP 成员排列、压缩方式和时间戳不影响摘要；ID、输入、输出或分值变化会改变摘要。长度分隔避免不同输入输出边界产生相同的串接内容。摘要是内容指纹，不能代替数据库版本号或比赛快照。

## 资源与完整性限制

| Limits 字段 | 默认值 | 约束 |
| --- | --- | --- |
| `MaxArchiveBytes` | 32 MiB | 实际归档字节数上限 |
| `MaxFileBytes` | 16 MiB | 每个输入或输出成员的展开字节上限 |
| `MaxTotalBytes` | 64 MiB | 全部输入输出展开字节之和 |
| `MaxCases` | 512 | 成对测试点数量，成员最多为两倍 |
| `MaxDirectoryBytes` | 1 MiB | 中央目录元数据预算 |

所有限额必须为有效正值。ZIP32 下 `MaxCases` 不得超过 32767；目录预算不能大于归档预算，单成员预算不能大于总展开预算。整数边界亦作检查，避免加一读取和累计计算溢出。

在 `archive/zip.NewReader` 分配成员列表之前，校验器预检 EOCD、中央目录实际字节范围、实际条目数、局部头、尺寸和文件名。**不能只信 EOCD 声明的数量，也不能等标准库读取全部条目后才检查数量。** 局部头与中央目录不一致、尺寸越界及 ZIP64 标记均拒绝。

展开阶段同时检查声明尺寸和实际读取量，按剩余预算有界读取，并完整读至 EOF。除标准库检查外，模块还独立计算实际 CRC32，与归档值比较，包括声明 CRC32 为零的成员，避免仅依赖标准库的特定分支。损坏 CRC、截断数据和伪造展开大小不会作为有效数据返回。

读取元数据、读取成员和返回结果前检查上下文取消；成员读取按至多 32 KiB 分块检查。归档与数据在内存中处理，后续 HTTP 层仍须限制同时上传/解析的数量，避免多个合法大包同时占满内存。

## 错误分类

调用者可使用 `errors.Is` 判断稳定分类，不应匹配错误字符串：

| 错误 | 含义 |
| --- | --- |
| `ErrInvalidArchive` | ZIP 格式、类型、压缩、头部、读取或完整性不合法 |
| `ErrInvalidPath` | 成员名称或文件类型不允许 |
| `ErrLimitExceeded` | 归档、成员、总展开、条目数量或目录预算超限 |
| `ErrInvalidLimits` | 调用者给出的限额无效 |
| `ErrPairing` | 数据集为空、配对缺失、重复或大小写冲突 |
| `ErrScore` | 分值表或总分无效 |
| `context.Canceled` / `context.DeadlineExceeded` | 调用被取消或超时 |

错误信息不包含测试数据内容或任意底层 I/O 错误。后续 API 应将这些分类映射为统一错误响应，不向普通用户泄露内部路径或实现细节。
